# CR7-05 — report autopilot and inbox (PO decision 2026-10-30)

PO: "legyen benne human control, de ne minden egyes claimbe … legyen automatikus a nagy része".
Status: implemented on branch `cr7-04-m07-attribution-robustness` (together with CR7-04); not yet applied to DEV;
CG7 stays OPEN; verdict unchanged ("OPERATIONAL VALUE NOT YET VALIDATED"); 0 / 6 real pilot cycles.

## What changes
* Migration `20261011004500_cr7_05_report_autopilot.sql` (46 migrations): table `report_autopilot`, HUMAN_ONLY
  `set_report_autopilot` (permission EVENT_ACTION, audit `REPORT_AUTOPILOT_SET`, exactly ONE report enabled at a time),
  worker helpers `auto_analysis_context`, `auto_analysis_eligible_claims`.
* Worker (`lfhe_orchestrator/autopilot.py`): while the switch is on, for claims of that report's context only —
  M03-classified claims → M05 → M06 → M07 (only if M06 recommends it; at most 20 automatic assessments per context)
  → M08 (existing chain). Deterministic `AUTO:` idempotency keys; failures never fail the model step that triggered them.
* Web: `/inbox` (everything that needs a human, in one place; batch confirm / reject of candidate events, each its own
  audited decision), Autopilot card on the Inbox and on the report page.

## What does NOT change (human-in-command)
The chain only *enqueues* jobs a human could request by hand. It never reviews, approves, promotes, changes an event
state, disposes a challenge flag, sets a final confidence, selects report content, or releases. Approval of
assessments, report gates (QA / content / security / release) and the role separation are unchanged. The REPLAY
corpus rule stays a human decision: with the autopilot ON every cutoff-eligible claim of that context is processed
(do not combine it with `--enqueue` on a corpus that contains snapshots you want excluded).
