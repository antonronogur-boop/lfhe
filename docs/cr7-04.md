# CR7-04 — M07 attribution robustness and rejection visibility

Status: implemented on branch `cr7-04-m07-attribution-robustness`; not yet applied to DEV; CG7 stays OPEN;
verdict unchanged ("OPERATIONAL VALUE NOT YET VALIDATED"); 0 / 6 real pilot cycles.

## Proven defect (P7-04 walkthrough, DEV, 2026-10-30)
Two real M07 runs (claude-sonnet-5-5) on two event versions were schema-valid but rejected by the closed
attribution rule (`ATTRIBUTION_MISSING`, `ATTRIBUTION_CONTRADICTS_WORKFLOW_STATE`). Attribution is decided by the
workflow (`lfhe.p4_attribution_required`), yet the prompt leaves that decision to the model. The UI showed only
"NEEDS HUMAN REVIEW"; the reason was visible only through SQL, and a re-request returned `ALREADY_COMPLETED`.

## Change (no prompt change, no change to an applied migration, no new permission)
1. `run_assessment`: when the rejection reasons are *only* attribution reasons, ONE additional, separately traceable
   model run (identical inputs) receives the exact findings (workflow requirement per statement, the cited claims'
   attributions). Ingestion is unchanged: a second violation is rejected as before (fail-closed).
2. Migration `20261011004400_cr7_04_assessment_rejection_visibility.sql`: an audited human re-request of M07 after a
   *rejected* output (outcome `REQUEUED_AFTER_REJECTION`, at most 3); view `lfhe.job_rejection_detail`.
3. Web: rejection reasons in plain language on the event page and `/jobs`; outcome text for the re-request.

## Not changed
Human approval, final confidence, gates, roles, cutoff semantics, idempotency after a recorded assessment.
